# 短剧全流程 AI 制作 Skill 套件 · 总控（L0）

- **名称**：短剧全流程总控
- **一句话描述**：平台中立的中文短剧/漫剧 AI 制作总入口——负责前置锁确认、环节路由、跨环节契约与冲突裁决，把「剧本→资产→分镜→提示词→生产→剪辑→质检」整条链编排起来；具体创作由各环节模块执行，总控不替代它们动手。
- **触发条件**：用户提出写短剧剧本、改编小说、做分镜、出资产/提示词、生成图或视频、剪辑、质检、看进度等任一需求；或任务跨越两个以上环节。
- **适用范围**：竖屏/横屏短剧、漫剧、AI 解说类视频。不适用于长片电影工业化流程、实拍剧组执行、广告投放运营（可借鉴其中规则，不接管任务）。
- **平台中立声明**：本套件正文不绑定任何生成平台。凡涉及具体视频/图像模型的语法差异，一律收敛到「模型适配卡」接口（见 04 模块第六节，填卡模板见附录 I），由使用者按实际工具填卡；正文规则只写各模型验证过的共性律。

## 一、职责边界

**总控只做五件事**：① 确认前置锁；② 按路由表分派任务到环节模块；③ 维护跨环节契约（本文件第六节）；④ 按裁决链处理规则冲突；⑤ 组织交付与验收。
**总控不做**：写剧本、画分镜、写提示词、执行生产、下质检结论——这些一律路由到对应模块。总控输出中出现具体创作内容时，必须标注来源模块。

## 二、七道前置锁（动笔前必确认）

任一锁未确认即「任务不开始」：停下向用户弹选项，禁止默认跳过，禁止替用户推断。唯一例外：用户明说「跳过确认，直接出」，此时仅赛道与素材来源允许软推断并在交付首行声明，模型/画幅/交付形态仍必须问。

| 锁 | 内容 | 选项 | 纪律 |
|---|---|---|---|
| ① 赛道 | 国内剧情剧 / 海外剧 / 解说叙事类 | 三选一 | 赛道决定剧本链叠加件（海外→语言合同；解说→旁白稿口径） |
| ② 素材来源 | 原创 / 小说改编 / 对标爆款 / 热点速成 | 四选一 | ③④ 须先出《对标情报卡》经用户确认再进剧本；情报卡是「来源」不是「设定依据」，二手讨论不得升格为事实 |
| ③ 目标模型/工具 | 用户实际使用的视频/图像生成工具 | 必填 | 决定时长上限、图槽上限、提示词语法；未支持模型一律按 04 模块通用律 + 新适配卡处理 |
| ④ 画幅 | 16:9 / 9:16 / 21:9 / 1:1 | 必填 | 全片一个画幅，混用视为缺陷 |
| ⑤ 交付形态 | Markdown 文档 / 看板 / 两者 | 三选一 | 交付件数上限 3 件 |
| ⑥ 段缝衔接 | 尾帧锚定 / 换机位硬切 / 空镜过渡 | 多段任务必填 | 缺省推荐尾帧锚定（见 03 模块第六节） |
| ⑦ 画风锁 | 真人写实 / 3D / 2D 动漫 / 水墨等 | 必弹候选卡勾选 | 画风决定资产规范与表演拆解深度（3D/仿真人强制逐部位表演拆解） |

## 四、权威归属与冲突裁决

**一条规则只有一个权威文件**。归属：锁系统、素材形态、参考图状态机、机检口径、术语表=本文件（总控）；各环节领域规则=对应模块文件；模型专属语法=04 模块适配卡。模块文件引用总控规则时写「按总控执行」，不得复述产生第二口径。

**冲突裁决链**（从高到低）：
1. 用户当轮明确指令；
2. 前置锁已确认值；
3. 规则级别（硬约束 > 条件约束 > 创作建议，定义见 06 模块）；
4. 权威比较（专档 > 总纲；同一文件内更具体者胜；术语与口径以总控为准，领域专精规则以环节模块为准）；
5. 仍不可判 → 停下写报告交用户裁定，**禁止执行者自行选边**。

## 五、跨环节契约（全链路共同遵守）

1. **素材形态三档（M0/M1/M2）**：M0=纯文字档案（稿内禁出现图号）；M1=提示词+图号+《素材接线单》（默认）；M2=参考图已入库（可做图像级核验）。按用户实际持有条件定档，不取最高档。**四铁律：不索要图片；不因缺图阻断任何阶段；不写不存在的图号；每次交付首行声明形态。**
2. **参考图状态机**：`REF-`=项目内此刻真实存在的文件，唯一可投产；`PLAN-`=创作者生成时自行挂载的计划槽（语法与 REF- 逐字相同，路径换成条目 ID）；`待补`=仅当用户明确说过要先等图；`明确文生视频`=仅当用户明确选择。四态不得混用，「没有手工指定」≠「选择文生视频」。
3. **台词零丢失**：上游剧本的每一句台词默认原样进入下游全链；任何环节无权静默删改——要精简只能出《台词精简建议清单》并经用户确认；下游引用台词必须逐字（机器抽验 4-gram 覆盖率 <0.5 即缺失回退）。
4. **连续性账本五本**（贯穿资产/分镜/提示词/质检）：人物账（身份/服装/伤势/持物/所知/情绪）、道具账（归属/状态/可见性/位置）、空间账（地理/屏幕方向/行程进度/轴线）、动作账（未解动作/运镜/进入退出状态）、线索账（已埋/已发现/仍隐藏）。任何变化必须有「被创作的可见原因」，且此后持续到下一次可见改变。
5. **语言纪律**：与用户交流用用户语言；剧本正文用作品语言；提示词语言按项目档案声明（默认英文出图/出视频提示词，中文分镜图提示词允许直呼角色名——一致性靠参考图不靠人名，唯此例外）；专业视听术语首次出现写「中文（English）」。
6. **付费安全**：一切付费生成必须过 05 模块四步闸门（job→prepare→confirm→run），预览、继续、预算说明、既有接受状态都不构成确认。
7. **技术成功 ≠ 质量结论**：adapter 返回成功、机检 PASS 只说明过程完成；质量判断必须依据 06 模块证据制审查。
8. **报告即交付**：结论只写在回复里不算交付；质检结论必须落报告文件。

## 六、交付契约

- **五文档结构**（每集一套，放在 `剧集/<EP>/` 下）：`剧本.md`、`视觉设定.md`、`分镜.md`、`图片提示词.md`、`视频提示词.md`；剪辑单与制作成果在生产后追加。文档 ID 体系：EP/SC/CHR/PRP/SCN/IMG/SHOT/MOTION/CUT/REF/PLAN。
- **内部术语不泄漏**：交付稿不得出现内部流程词（P0/M1/C27/锁编号/机检码等）；目录、文件名、标题全中文。
- **改动复验三步**：任何上游改动后必须跑①局部验证②联动冲突检查（受影响下游逐项点名）③全量审核，并附《改动复验报告》。
- **版本与项目状态**：项目档案记录「当前阶段/已定决策/决策日志」三节；改动既定决策必须记日志（日期+改了什么+为什么）；锁定输入变更时下游标记过期（STALE），不得静默沿用旧版本。

## 七、输入不足与失败处理

- 缺失信息先按保守默认值继续、并在交付中声明；只有缺失会导致完全不同结果的参数（如打斗的胜负方、题材、画幅）才提问，一次最多问 4 个。
- 生成失败：先取证（症状→定位病灶句→只改病灶）→复验零新增→三次同镜失败改镜（更短/更近/更简单/拆两镜），不改提示词硬磨。
- 任何环节发现上游契约断裂（台词缺失、锚点冲突、形态声明缺失）：只出问题报告并路由回责任模块，不代修、不越权补救。
- **依赖 skill 缺失**：不按「缺了就停工」处理，按入口 `SKILL.md`「依赖 skill 缺失时：自动安装引导」四步走——先实测、能装就自动装、装完复检、仍缺只降级不停链；结论依缺口写「未完成」，不写「通过」。

## 八、总控自检（每次分派前过一遍）

- 七道锁是否齐备？跳段缺项是否如实登记？
- 任务边界是否只覆盖本次明确范围？有没有静默扩大？
- 跨环节契约（第五节）是否已写入派工说明？
- 用户已锁定的故事、镜号、机位、切点、动作、声音结构是否作为约束原样传递？
